# Spec: 系统音频焦点仲裁、全流转防外放与动态路由自愈 (System Audio Focus Arbitration, Full-Lifecycle Becoming Noisy Guard & Dynamic Route Resilience)

Status: completed

## Problem Statement

作为在 Android 移动端使用 WebDavPlayer 欣赏远程音乐与有声书的用户，在日常通勤、驾车连接车载蓝牙、佩戴无线耳机以及应对系统通话打断时，面临以下严重违背主流商业播放器（如网易云音乐、Spotify、Apple Music）规范的声学、生命周期与交互缺陷：

1. **音频焦点治理撕裂与底层越权穿透（Audio Focus Seam Bypass）**：
   系统来电或导航提示打断时，现有的焦点处理器直接绕过应用会话层，穿透调用底层流式引擎的暂停与播放，破坏了 ADR-0018 确立的单向意图架构。应用会话层无法感知物理发声的中断，导致弱网看门狗仍在空跑、播放时钟与毫秒进度无法对齐持久化；若在应用冷启动未完成物理流装配时收到焦点恢复，直接调用底层播放会导致播放器陷入无声哑音。
2. **通话被打断期间主动暂停，挂断后“幽灵复播”（Ghost Resumption）**：
   当电话呼入导致音频瞬态失焦时，系统记录了待恢复状态。若用户在通话期间在通知栏、锁屏或车机中枢上主动点击了“暂停”，挂断电话后应用完全无视用户的主动意图，强行自动恢复播放，造成极大的困扰与尴尬。
3. **永久失焦未释放系统注册（Permanent Focus Loss Leak）**：
   当用户打开其他外部媒体应用（如启动视频或第三方音乐应用）导致永久失去焦点时，播放器仅暂停了音频流，却从未向系统注销音频焦点请求，导致应用持续霸占系统的音频焦点仲裁栈。
4. **系统与应用层双重音量压低（Double Ducking Degradation）**：
   在接收导航提示音或系统短通知时，Android 8.0+ 混音系统已默认进行硬件级声音压低，而焦点处理器又在应用层将音量强制下调至 20%，叠加衰减导致声音几乎彻底静音。
5. **起播与切歌缓冲阶段（Buffering）防外放真空盲区（Becoming Noisy Gap）**：
   现有的防意外外放保护仅在音频实际发声（Playing）时处于激活状态。在点击播放、切歌或网络抖动重新缓冲的 1~3 秒期间，若拔出有线耳机或蓝牙音箱电量耗尽突发关机，系统发出的外放拦截广播会被完全漏失；数秒后流数据就绪进入播放，声音会毫无阻拦地直接从手机扬声器大声公放。
6. **系统“媒体输出切换器”（Media Output Switcher）路由漏失**：
   音频路由监听仅依赖物理硬件插拔回调。当用户在手机系统的控制中心或音量浮窗面板中手动切换发声设备（例如在已配对的蓝牙音箱与无线耳机之间流转）时，没有硬件增减事件触发，导致底层发声管道无法感知并刷新缓冲区，非标准采样率音频随即诱发时钟错位与硬件挂起静音。
7. **规范化重采样管道遇非常规编码抛出崩溃**：
   当前置重采样处理器遇到非 16-bit 浮点 PCM 音频流时，直接抛出未捕获异常导致播放管道崩溃中断。

## Solution

在应用会话层（`MusicPlayerAppSession`）与播放宿主适配器（`PlaybackSessionHost`）建立严密、单向的系统中断仲裁与全生命周期声学防御架构，彻底对齐主流商业播放器的工程标准：

1. **音频焦点仲裁收拢至高层应用会话接缝（Audio Focus Intent Harmonization）**：
   - 彻底斩断焦点处理器对底层播放引擎的越权调用。将瞬态失焦（`AUDIOFOCUS_LOSS_TRANSIENT`）、永久失焦（`AUDIOFOCUS_LOSS`）与恢复（`AUDIOFOCUS_GAIN`）全量转化为标准应用播放意图（`Playback Intent`），统一汇入应用会话层进行集中状态机仲裁。
   - 焦点丢失触发的暂停享有完整的应用会话级保障：重置弱网看门狗、同步更新锁屏与通知栏状态机、精确落盘当前毫秒播放进度。
   - 焦点恢复起播由应用会话层统一仲裁；若处于冷恢复现场，自动完成音频流重新装填与无声自愈。
2. **主动暂停仲裁与幽灵复播彻底阻断（Ghost Resumption Guard）**：
   - 建立单向意图仲裁机制：一旦用户在通话期间或失焦期间通过任何渠道（通知栏 Action、锁屏卡片、屏幕 UI、线控按键）主动派发了暂停或停止意图，立即原子化清除“失焦待恢复”标记。
   - 通话结束收到系统焦点恢复通知时，若待恢复标记已被清除，严格维持暂停状态，绝对不发生幽灵自动复播。
3. **永久失焦主动注销与生命周期归位（Permanent Focus Loss Abandonment）**：
   - 当收到永久失焦事件时，应用会话层立即执行受控暂停，并同步触发系统音频焦点释放，从系统焦点管理栈中完全退出。
4. **规范化系统压低策略（Ducking Normalization）**：
   - 规范化 Android 8.0+ 焦点请求配置，将声音衰减交给系统混音层统一裁决，杜绝应用层二次重复压低导致的音量湮灭。
5. **全流转状态防意外外放坚壁（Buffering Becoming Noisy Shield）**：
   - 将防外放拦截接收器的监听生命周期扩展至缓冲阶段（`Buffering`）。凡用户意图处于起播、换轨或网络恢复中，均严密布防 `ACTION_AUDIO_BECOMING_NOISY` 广播。
   - 在缓冲期间侦测到耳机拔出或蓝牙断连，立即拦截并触发会话级安全暂停，取消起播意图；当底层流缓冲完成时，严格维持在安全暂停状态，彻底消灭安静场合的大声公放事故。
6. **双轨音频路由自愈与系统切换器联动（Dynamic Route Switcher Observer）**：
   - 升级音频路由感知器为双轨监听架构：物理设备插拔回调（通过 `AudioDeviceCallback` 感知硬件增减）与系统媒体输出切换器流转监听（API 30+ 通过 `MediaRouter2.TransferCallback` 原生监听控制中心手动设备切换）协同运作；底层 `AudioRouting` 接口作为保留测试与扩展接入点（标记 `@VisibleForTesting`）。
   - 无论通过拔出耳机还是在系统媒体输出弹窗中手动切换输出端口，均能在毫秒级内触发底层音频发声管道缓冲区刷新与时钟重同步，消除声道假死与静音空跑。
7. **规范化重采样弹性直通（Canonical Resampling Robustness）**：
   - 重采样处理器增加弹性格式协商机制：凡输入格式为高解析度或非 16-bit 浮点音频流，一律保持非破坏性直通，杜绝异常崩溃。

## User Stories

1. 作为在办公室使用蓝牙音箱收听音乐的用户，当有突发电话呼入导致音乐被系统暂停时，我希望应用会话层能够精确冻结播放进度并停止弱网看门狗，以便不会在后台消耗多余网络流量。
2. 作为在通话中选择手动操作的用户，当通话期间我在锁屏通知栏主动点击了“暂停”按钮时，我希望通话结束后播放器保持暂停，以便绝对不会突然自动复播吓到周围的人。
3. 作为在驾车时收听长音频的用户，当来电结束后我挂断电话且此前未手动暂停，我希望音乐能自动平滑恢复播放，以便我无需分心操作手机。
4. 作为使用第三方音乐 App 临时听歌的用户，当我切换到其他应用播放歌曲导致当前播放器永久失去焦点时，我希望当前应用立即安全暂停并向系统彻底释放音频焦点，以便不干扰其他应用的正常发声。
5. 作为在高速公路上依赖导航提示音的车主，当导航语音播报时，我希望背景音乐只是被适度压低音量，而不是被双重衰减导致完全听不见旋律。
6. 作为从应用冷启动状态恢复收听的用户，当应用刚被拉起且音频流尚未物理装填时突遇来电并挂断，我希望应用会话层能通过冷恢复机制无缝起播，而不是陷入空转哑音。
7. 作为在安静图书馆点选新歌收听的学生，当点击歌曲正在缓冲加载的 2 秒内耳机插头被意外拽出时，我希望应用立即取消播放并将状态定格为暂停，以便缓冲完毕后绝对不会从手机扬声器突然大声外放。
8. 作为在电梯等弱网环境下收听的用户，当音频由于网络卡顿正在重新缓冲时蓝牙耳机突发断开，我希望防外放机制依然能够生效拦截，以便走出电梯网络恢复时声音不会意外公放。
9. 作为拥有多套音频设备的用户，当我正在通过蓝牙音箱播放，并在 Android 系统的音量面板“媒体输出”菜单中手动切换为蓝牙耳机时，我希望声音立刻顺畅转移至耳机中出声，以便无需暂停重播。
10. 作为收听 22050Hz 老旧评书的用户，当我在系统通知栏的媒体设备切换器中来回切换扬声器与耳机时，我希望发声管道主动重置时钟，以便进度条与实际发声严格同步且不发生静音空跑。
11. 作为无损音频发烧友，当播放包含浮点或特殊位深的高保真音频时，我希望重采样处理器安全直通而不抛出崩溃，以便享受稳定流畅的母带回放。
12. 作为使用系统通知栏播控的用户，当电话打断发生时，我希望通知栏上的播放/暂停图标毫秒级刷新为暂停状态，以便 UI 状态与实际声学状态完全同步。
13. 作为使用智能手表控制媒体的用户，当电话挂断自动恢复播放时，我希望手表端能够收到准确的播放状态流，以便界面信息保持一致。
14. 作为在夜间睡眠前收听音频的用户，当蓝牙音箱因低电量自动关机时，即使播放器正处在切歌缓冲瞬间，我希望应用也能坚决守住静音防线，以便家人不被意外惊醒。
15. 作为电量敏感型用户，当音频焦点永久失去触发暂停时，我希望 CPU 唤醒锁与 Wi-Fi 锁立即被释放，以便应用在后台不会造成额外的电量损耗。
16. 作为经常遭遇短暂网络抖动的用户，当电话挂断恢复播放与网络自动重试同时发生时，我希望应用会话层能够以单一仲裁源处理，避免状态机发生冲突震荡。
17. 作为在通话中误触耳机线控按键的用户，当我在通话期间不小心按了耳机暂停键，我希望挂断电话后应用尊重我的最后一次按键意图，维持在暂停状态。
18. 作为跨版本 Android 系统的用户，当在 Android 10 到 15 的各类设备上收听时，我希望音频焦点和外放拦截行为表现出完全一致的可靠性。
19. 作为关注数据一致性的用户，当系统音频焦点被抢占导致暂停时，我希望当前进度能够立即异步刷盘入库，以便即使后台进程随后被系统杀除进度也不会丢失。
20. 作为长时间后台收听的用户，当瞬态焦点丢失（如微信语音提示音）结束后，我希望音量平滑渐变恢复原状，以便听觉体验平顺不突兀。
21. 作为在驾驶过程中使用车载方向盘按键的用户，当车载蓝牙发生音频路由内部迁移时，我希望发声管道自动完成时间戳对齐，以便切歌与寻道依然精准。
22. 作为编写自动化集成测试的架构开发者，我希望通过统一的高层应用会话接缝和宿主接缝注入模拟焦点与广播事件，以便能以确定性的方式自证所有声学边界条件。
23. 作为代码库维护者，我希望底层流式渲染管道完全剥离业务焦点仲裁逻辑，以便渲染管道保持纯粹的高内聚与低耦合。
24. 作为收听虚拟分轨专辑的用户，当电话打断触发暂停并挂断恢复时，我希望虚拟时间轴能精确停留在当前分轨的断点，以便无需重新从整张专辑开头寻找进度。
25. 作为收听多曲目连续循环的用户，当一首歌曲刚刚结束并进入下一首起播缓冲时，如果此时摘下耳机，我希望新曲目立刻停止发声，以便符合防外放的行业直觉。

## Implementation Decisions

### 1. 焦点处理器与应用会话层的意图接缝深化

- **单向意图仲裁契约**：
  从焦点处理模块中彻底移除对底层播放引擎的直接调用。焦点处理模块持有应用会话层接缝引用（`MusicPlayerAppSession`），将系统焦点变更映射为标准会话意图：
  - `AUDIOFOCUS_LOSS_TRANSIENT`：派发应用会话级暂停（`appSession.pause()`），并在会话层内部原子化标记 `pausedByTransientAudioFocus = true`。
  - `AUDIOFOCUS_GAIN`：会话层检查 `pausedByTransientAudioFocus`。若为 `true`，清除标记并调用 `appSession.play()` 恢复回放；若为 `false`（说明期间用户已主动暂停），则静默忽略，坚决维持暂停。
  - 用户主动行为清空机制：任何来自外部用户的主动意图（`pause()`、`togglePlayPause()`、`stop()`、`playDirectoryTrack()`）均强制重置 `pausedByTransientAudioFocus = false`，彻底根除幽灵复播。
- **永久失焦主动退栈**：
  收到 `AUDIOFOCUS_LOSS` 时，派发 `appSession.pause()` 并立即执行 `abandonAudioFocus()`，彻底清除待恢复标志并释放系统焦点持有权。
- **压低规范化**：
  针对系统支持的自动压低（Can Duck）行为，移除应用层与系统层的重复相乘，统一音量生命周期恢复。

### 2. 全流转防意外外放坚壁

- **监听生命周期扩展**：
  在播放宿主适配器中，将 `ACTION_AUDIO_BECOMING_NOISY` 广播接收器的注册生命周期扩展为：
  - 在 `PlaybackState.Playing` 或 `PlaybackState.Buffering`（且 `playWhenReady == true`）时均保持注册；
  - 仅在转换至用户意图暂停（`PlaybackState.Paused`）、空闲（`PlaybackState.Idle`）或播放结束（`PlaybackState.Ended`）时注销。
- **缓冲拦截与安全降级**：
  在缓冲阶段接收到断连广播时，100% 经由 `appSession.pause()` 派发。会话层立即将意图翻转为暂停，取消看门狗重试并释放硬件锁；底层引擎完成缓冲后检测到 `playWhenReady == false`，自动停留在准备就绪暂停状态，严禁发声。

### 3. 双轨音频路由变动监听与 AudioSink 自愈

- **双轨感知器架构**：
  音频路由监听器融合两路输入源：
  1. `AudioDeviceCallback`：侦测物理输出设备的硬件插拔与蓝牙连接断开；
  2. `MediaRouter2.TransferCallback`（API 30+ 系统媒体路由）与 `AudioRouting.OnRoutingChangedListener`（通过注入的活跃发声管道，标记 `@VisibleForTesting`）：实时捕获用户在系统控制中心“媒体输出切换器”中的手动设备路由变更。
- **无感缓冲区刷新与重同步**：
  任一轨道触发有效发声节点漂移时，统一调度 `activeAudioSink?.flush()`，清空旧设备的驻留 PCM 数据，触发驱动时钟重新握手，彻底消除静音空跑与假死。

### 4. 规范化重采样管道容错

- **高解析度与浮点弹性直通**：
  重采样处理器在检测到输入编码非标准 16-bit PCM 时，若采样率已达到标准阈值（`>= 44,100 Hz`）或属于非破坏性高保真流，保持直通；对非标低采样率进行受控检查，杜绝未经捕获的崩溃中断。

## Testing Decisions

### 1. 优质测试准则（Behavioral over Implementation Details）

- 仅从外部环境向系统输入真实事件（模拟音频焦点事件、发送系统广播、触发设备路由变更），并断言应用会话层的公开响应式状态（`sessionState`）、播放进度以及对外可观测的会话意图。
- 严禁断言私有布尔变量或框架内部回调层级，确保测试具备重构免疫力。

### 2. 选定测试接缝（The Seam）

- **最高主测试接缝**：应用会话层（`MusicPlayerAppSession`）与前台宿主层（`PlaybackSessionHost`）。
  - **焦点打断与恢复接缝**：在 `PlaybackSessionHostTest` 中模拟 `AUDIOFOCUS_LOSS_TRANSIENT`，断言会话状态跃迁为 `Paused`；模拟通话期间用户主动点击暂停，断言随后的 `AUDIOFOCUS_GAIN` 不会触发播放。
  - **冷启动焦点恢复接缝**：在空物理流状态下触发焦点恢复，断言会话层正确调度装载逻辑。
  - **永久失焦释放接缝**：模拟 `AUDIOFOCUS_LOSS`，断言系统 `abandonAudioFocusRequest` 被调用，会话进入稳定暂停。
  - **缓冲期防外放接缝**：在 `PlaybackState.Buffering` 状态下派发 `ACTION_AUDIO_BECOMING_NOISY`，断言接收器处于活跃状态且成功触发 `appSession.pause()`，状态机稳定收敛为 `Paused`。
  - **双轨路由自愈接缝**：在 `AudioRoutingObserverTest` 中验证发声设备手动切换触发刷新回调。
  - **弹性重采样接缝**：在 `CanonicalResamplingAudioProcessorTest` 中验证非 16-bit 与高保真浮点流平稳直通不崩溃。

### 3. 代码库中的既有测试前案（Prior Art）
