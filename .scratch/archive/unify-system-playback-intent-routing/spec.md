# Spec: 统一系统级播控意图接缝至应用会话层 (Unify System Playback Intent Routing Through App Session)

Status: resolved

## Problem Statement

作为在 Android 移动端使用 WebDavPlayer 欣赏远程音乐的用户，经常在日常通勤或熄屏休眠时使用耳机线控按键、车机蓝牙中控或系统常驻通知栏进行播放控制。然而，在现有实现中，系统级播控存在意图派发分裂与状态失步问题：

1. **冷恢复（Cold Restore）播放失灵（Bug）**：当应用被系统置于后台休眠或进程终止冷启动后，用户点击系统通知栏或蓝牙耳机的“播放”键，系统没有任何声音。这是因为外部播放指令绕过了应用会话层，直接调用了处于空闲状态的底层音频播放引擎，而底层引擎缺乏重新装载当前曲目和网络凭据的会话恢复逻辑。
2. **停止操作清理不完整（Bug）**：当用户通过车载蓝牙或实体线控按下“停止”（Stop）按键时，外部指令直插底层引擎关闭音频流，却跳过了应用会话层的清理流程，导致虚拟分轨时间线残留、弱网看门狗定时器泄漏、周期性刷盘未正常终止，并在下一次应用冷启动时误判为非正常退出而触发不必要的恢复逻辑。
3. **架构概念撕裂与循环依赖**：系统级“下一首/上一首”指令路由到了高层应用会话层，而“播放/暂停/停止”指令却短路到底层引擎。为了支持切歌，底层引擎通过幽灵反向通道持有上层会话的可空引用，违背了单向依赖与流式渲染管道（Streaming Playback Pipeline）的架构原则。

## Solution

建立统一、单向的系统级播控意图接缝（Playback Intent Seam）：

1. **统一意图路由**：所有来自外部操作系统（包括蓝牙耳机实体按键、车载控制协议、系统媒体按钮广播、系统通知栏操作按钮以及前台媒体播放器命令请求）的播放控制意图（Play、Pause、TogglePlayPause、Stop、SkipToNext、SkipToPrevious），100% 汇入高层应用会话层（`MusicPlayerAppSession`）统一仲裁。
2. **根治冷恢复与状态清理缺陷**：
   - 当接收到播放/暂停意图时，由应用会话层统一判定当前回放状态机。若处于空闲但存在未播放完毕的会话曲目，自动触发完整的冷恢复逻辑（重新装载媒体流、恢复断点偏移、同步元数据并提权前台服务）。
   - 当接收到停止意图时，触发完整的会话级退出序列（释放预卷缓冲流、停止周期刷盘、清理虚拟时间轴、重置弱网看门狗定时器，并以安全退出标记持久化会话快照）。
3. **斩断底层反向依赖**：
   - 彻底删除底层播放引擎对高层应用会话层的反向持有通道及延迟注入方法。
   - 媒体会话回调组件在构造或初始化阶段直接绑定应用会话层，不再持有或调用底层播放引擎，让底层播放引擎退化为纯粹、无依赖、高内聚的流式音频渲染管道。
4. **净化测试表面**：
   - 测试直接基于媒体回调入口与应用会话层接缝进行验证，断言会话层接收到的标准意图，彻底移除对底层引擎内部调用计数的冗余测试桩。

## User Stories

1. 作为使用蓝牙耳机的用户，当我在应用冷启动后点击耳机单击键触发播放时，我希望应用能自动唤起会话层的冷恢复机制并继续播放上次暂停的音乐，而不是毫无响应。
2. 作为使用蓝牙耳机的用户，当音乐正在播放时我单击耳机键，我希望应用会话层接收到播放暂停切换意图，暂停当前流并安全刷盘保存进度。
3. 作为使用车载蓝牙中控的用户，当我在方向盘上按下独立的“播放”（Play）按键时，我希望无论播放器处于暂停还是冷启动空闲状态，都能正确开始发声并同步通知栏状态。
4. 作为使用车载蓝牙中控的用户，当我在方向盘上按下独立的“暂停”（Pause）按键时，我希望音乐立即平滑暂停，且当前播放进度被精确记录在本地会话中。
5. 作为使用车载蓝牙中控的用户，当我在方向盘上按下独立的“停止”（Stop）按键时，我希望不仅底层物理流立即终止，会话层内部的虚拟时间线、弱网缓冲看门狗定时器和定期持久化任务也全部干净释放。
6. 作为使用实体按键线控的用户，当我连续点击或长按挂断/通话键（Headset Hook）时，我希望该事件统一由应用会话层作为播放/暂停意图处理，与屏幕 UI 上的播放按钮行为完全一致。
7. 作为查看系统通知栏的用户，当我点击通知栏自定义 Action 中的“播放”按钮时，我希望该操作能够穿透到应用会话层，即使服务刚刚经历过前台降级也能可靠重新起播。
8. 作为查看系统通知栏的用户，当我点击通知栏自定义 Action 中的“暂停”按钮时，我希望该操作通过会话层暂停流媒体播放，并进入前台降级宽限期，保留通知栏卡片。
9. 作为收听 CUE 虚拟分轨整轨音频的用户，当我在耳机上线控点击“下一首”时，我希望指令由应用会话层识别为分轨切歌，仅更新虚拟时间轴与元数据，而不破坏底层的物理网络长连接。
10. 作为收听 CUE 虚拟分轨整轨音频的用户，当我在耳机上线控点击“上一首”且分轨进度大于 3 秒时，我希望应用会话层能精确重置回当前分轨起点并继续播放。
11. 作为播放列表处于随机模式下的用户，当我在通知栏或线控点击“下一首”时，我希望应用会话层按照自身的确定性洗牌算法挑选下一曲，而不是由底层引擎随意跳跃。
12. 作为处于极弱网络环境下的用户，当音频遇到缓冲卡顿且看门狗定时器正在计时重连时，如果我点击线控“暂停”或“停止”，我希望会话层能立即取消看门狗重试并释放网络连接，杜绝后台无谓跑流量。
13. 作为使用智能手表媒体控制卡片的用户，当手表通过系统 MediaSession 发送标准切歌或播放指令时，我希望会话层能够以完全统一的意图处理并返回执行成功状态。
14. 作为维护代码库的架构开发者，我希望底层流式渲染管道模块完全不感知、不导入上层应用会话域对象，保持纯粹的单向架构依赖。
15. 作为编写自动化测试的开发者，我希望在测试系统级媒体按键事件时，能够通过传入仿真会话层直接断言业务意图的派发，不再需要编织底层虚假的播放器状态桩。

## Implementation Decisions

### 1. 媒体会话回调组件重构为纯意图派发器

- **依赖单向化**：从媒体会话回调组件中移除对底层音频播放引擎的所有直接依赖（包括构造参数与属性）。
- **非空意图宿主**：媒体会话回调组件在装配完成时持有非空的应用会话层接缝引用，专职负责将 Android OS 传入的底层事件（如 Media Button KeyEvent、PlayerCommandRequest）翻译为高层语义意图。
- **意图映射标准化**：
  - `KEYCODE_MEDIA_PLAY` 映射为会话层的播放意图。
  - `KEYCODE_MEDIA_PAUSE` 映射为会话层的暂停意图。
  - `KEYCODE_MEDIA_PLAY_PAUSE` 与 `KEYCODE_HEADSETHOOK` 映射为会话层的播放/暂停翻转意图（由会话层自行根据当前响应式状态裁决，不再在回调层读取底层引擎状态）。
  - `KEYCODE_MEDIA_STOP` 映射为会话层的停止意图。
  - `KEYCODE_MEDIA_NEXT` 与 `COMMAND_SEEK_TO_NEXT(_MEDIA_ITEM)` 映射为会话层的下一首切歌意图。
  - `KEYCODE_MEDIA_PREVIOUS` 与 `COMMAND_SEEK_TO_PREVIOUS(_MEDIA_ITEM)` 映射为会话层的上一首切歌意图。

### 2. 系统媒体服务通知栏 Action 路由归一

- **消除底层直连**：系统前台媒体服务在响应通知栏自定义广播指令时，彻底移除直接调用播放宿主 `play()`、`pause()` 的代码路径。
- **经由会话层派发**：通知栏中的播放、暂停、切歌动作与媒体按钮事件汇聚至同一业务接缝，全部委托至应用会话层对应的业务方法。

### 3. 底层流式渲染引擎幽灵反向接口剥除

- **删除反向通道**：从底层媒体播放引擎与播放宿主服务中彻底删除 `setAppSession` 相关的反向注入接口与属性。
- **净化底层包依赖**：底层播放引擎所属模块完全移除对应用会话层包的导入，严守单向依赖原则（应用会话层依赖底层播放引擎接口，底层引擎对会话层完全无知）。

### 4. 依赖注入与装配拓扑一次性绑定

- **一次性装配契约**：在应用启动初始化时，统一解决播放引擎与会话层之间的创建依赖。由于底层引擎在创建 MediaSession 时需要绑定 Callback，而 Callback 需要调用会话层，采用明确的一次性绑定机制（在 Application 初始化阶段完成关联后即封闭为不可变状态），消除运行期可变与时序空窗风险。

## Testing Decisions

### 1. 什么是高质量的意图接缝测试

- **只测试外部行为，不测试实现细节**：测试应当模拟外部世界向系统输入的真实事件（如构建携带按键 KeyEvent 的 Intent，或触发 MediaSession 命令回调），并仅断言应用会话层对外暴露的意图接口是否被正确调用。
- **消除对底层物理引擎的虚假验证**：不再测试底层音频播放引擎是否被直接调用，因为底层引擎的起播与暂停属于会话层仲裁后的次生副作用，由会话层自身的单元测试负责。

### 2. 待测模块与测试覆盖要求

- **媒体会话回调测试模块**：
  - 覆盖 Play、Pause、PlayPause、Stop、Next、Previous 各按键事件的正常派发。
  - 覆盖 HeadsetHook 按键的翻转意图派发。
  - 覆盖 ActionUp 抬起事件的静默过滤（不产生重复意图）。
  - 覆盖未知按键事件与非媒体意图 Intent 的安全忽略。
  - 覆盖 MediaSession 标准命令请求（SeekToNext / SeekToPrevious）向会话层的准确转发。
- **系统媒体服务广播交互测试**：
  - 覆盖通知栏 ActionPlay、ActionPause、ActionNext、ActionPrevious 意图向会话层的统一转发。

### 3. 代码库中的既有测试前案（Prior Art）

- 媒体会话回调单元测试集（`WebDavMediaSessionCallbackTest`）已使用 Robolectric 模拟 Android Intent 与 KeyEvent。现有的测试桩通过断言仿真引擎的计数器进行验证，本次重构遵循“替换而非层叠（Replace, Don't Layer）”原则，直接删除针对底层引擎计数的旧断言，重写为针对仿真会话层（`FakeMusicPlayerAppSession`）意图计数的断言。
- `FakeMusicPlayerAppSession` 已内置 `playCount`、`pauseCount`、`togglePlayPauseCount`、`stopCount`、`skipNextCount`、`skipPreviousCount` 等完整的测试观测探针，无需引入额外的新桩。

## Out of Scope

1. **CUE 虚拟分轨与目录解析模块重组**：虽然 CUE 解析在会话层与表现层之间存在深度不足的问题（候选 2），但本规范仅聚焦于系统播控意图的单向汇流，不变更 CUE 文本抓取或解析的仓储层实现。
2. **应用会话层内部韧性策略与持久化拆解**：会话层内部代码量过大（候选 3）的问题不在此处展开，会话层对意图的具体内部处理逻辑保持不变。
3. **UI 层 14 项回调参数折叠**：全屏播放器与小播放器的 UI 参数签名收拢（候选 5）属于后续前端重构工作，不在本次系统级播控接缝范围。
4. **音频解码器与 ExoPlayer 缓冲参数调整**：音频提取策略、OkHttp 数据源重试策略与硬件唤醒锁保持现状。

## Further Notes

- 本方案严格遵从并闭环了 **ADR-0016**（加深播放引擎为流式渲染管道，收拢切歌意图）与 **ADR-0018**（统一系统级播控意图路由至应用会话层）的架构决议。
- 本方案直接修复了由底层直接绕过导致的**冷恢复无声**与**Stop 键跳过资源清理**两项隐蔽运行时缺陷。
- 术语已在 `GLOSSARY.md` 中固化定义，包括 `Playback Intent`、`Cold Restore`、`Streaming Playback Pipeline` 与 `Session-Managed Queue Progression`。
