# Spec: Stream Pipeline and Session Host Decoupling

Status: completed

## Problem Statement

作为 WebDavPlayer 的用户与开发者，当前在音频流式播放管道与系统服务宿主层之间存在严重的架构摩擦与职责撕裂：

1. **接缝被跨层向下强转击穿**：系统服务宿主模块表面上实现了音频播放引擎接口，但内部多达 5 处强行向下类型转换，穿透至底层特定的 Media3 引擎实现，使得“接口”形同虚设；
2. **硬件休眠锁治理混乱且双重调用**：用于保障锁屏流畅流式播放的 CPU 唤醒锁与 Wi-Fi 高性能锁（Dual Streaming Hardware Locks），同时被底层播放引擎与上层服务宿主双重监听并反复申请/释放，甚至被多余地注入进完全无关的媒体源适配器中；
3. **系统媒体会话反向寄生与迂回调用**：负责系统通知栏与锁屏播控的 MediaSession 被深埋在底层物理音频渲染引擎内部，导致切歌与播控事件必须跨层迂回向底层注入回调函数，破坏了领域事件与播控意图的单向传递；
4. **测试表面与生产运行失真**：由于状态双向流动与多处强转，测试夹具被迫测试被穿透的内部状态而非真正的行为接缝，增加了回归隐患与维护负担。

## Solution

将底层物理音频流回放与系统前台宿主彻底正交解耦，重构为两个职责纯净的高内聚深层模块：

1. **纯粹流式播放管道（Streaming Playback Pipeline）**：底层播放引擎专注于物理音频流解码、PCM 升采样、自适应弱网缓冲与硬件休眠锁的自主闭环，彻底移除所有关于系统通知、媒体会话回调或切歌意图的反向注入；
2. **统一系统会话宿主（Playback Session Host）**：服务宿主专注于 Android 前台服务生命周期、15 分钟前台延迟降级、系统音频焦点、外放拔出阻断与系统 MediaSession 的统一构建与派发，彻底消除对底层引擎实现类的向下类型强转；
3. **消除冗余依赖泄漏**：清除媒体源适配器等中间组件中多余持有的锁对象，恢复单向、确定的依赖拓扑。

## User Stories

1. 作为一名音乐爱好者，我希望在锁屏或后台长时间聆听 WebDAV 远程无损音乐时，CPU 唤醒锁与 Wi-Fi 高性能锁能够精准、单一地随播放与缓冲状态自动持有与释放，以便在零断流、零卡顿的同时获得最低的电池功耗。
2. 作为一名移动端用户，我希望在蓝牙耳机或车载设备上点击“下一首”或“上一首”时，系统 MediaSession 能够直接派发播控意图至会话层，以便切歌能够立即响应，杜绝因底层引擎迂回回调失败导致的无声或跳曲异常。
3. 作为一名用户，我希望在耳机意外断开或蓝牙音箱电量耗尽关机时，前台服务宿主能即刻拦截外放事件并优雅暂停播放，以便保护隐私并防止公共场合尴尬外放。
4. 作为一名发烧友用户，我希望在非标准低采样率（如 22050Hz/16000Hz）音频流与不同蓝牙/扬声器设备切换时，底层音频渲染引擎能自主感知路由漂移并刷新 AudioSink 缓冲区，以便彻底消除“进度条在走但扬声器无声”的假死问题。
5. 作为一名用户，我希望在音乐暂停后 15 分钟内点击通知栏播放按钮时，前台服务能无缝恢复出声，在 15 分钟超时后优雅释放前台身份，以便兼顾瞬时续播与系统资源节约。
6. 作为一名开发者，我希望通过统一的流式播放引擎接口与底层管道交互，无需任何跨层向下强转，以便未来的播放引擎实现能够自由替换和扩展。
7. 作为一名开发者，我希望测试用例只跨越真实的公共行为接缝，无需在宿主测试和引擎测试中重复验证双重锁逻辑，以便提升测试信度与重构安全性。

## Implementation Decisions

1. **硬件锁归属内化至底层播放引擎（Hardware Locks Enclosure）**：
   - 彻底内化：将 Dual Streaming Hardware Locks 的持有与释放生命周期完全收敛在底层播放引擎（Streaming Playback Pipeline）内部；当底层引擎进入 Playing 或 Buffering 状态时自动加锁，进入 Paused、Idle、Error 或 Ended 时自动释放锁。
   - 宿主解脱：系统服务宿主不再重复监听状态并调用加解锁，消除两端状态监听时序竞态。
   - 适配器瘦身：从媒体源适配器中彻底删除多余的硬件锁构造参数与暴露属性，消除无意义的跨层传递。

2. **MediaSession 生命周期与装配提升至系统宿主（MediaSession Hoisting）**：
   - 所有权转移：系统 MediaSession 的构建、生命周期管理与释放全权移交至系统服务宿主。
   - 管道纯净化：底层播放引擎退化为纯粹提供核心播放器能力的容器，不再构建或管理 MediaSession。
   - 铲除反向注入：底层播放引擎彻底删除会话回调属性、上一曲/下一曲回调函数，彻底根除反向回调回旋镖。
   - 统一播控通道：系统通知栏与线控按键通过宿主绑定的媒体会话回调，单向派发至应用会话层。

3. **彻底消除宿主内部全部跨接缝向下强转（Zero Downcasts Contract）**：
   - 消除全部强转：系统服务宿主内部严格面向流式播放管道的公共接缝编程，严禁出现任何向下强转至具体引擎实现类的代码。
   - 路由事件通道化：将音频路由漂移变更的处理通过播放引擎接缝暴露的标准化方法调用，或由引擎内部独立监听与自愈，宿主不再通过强转访问内部观察者。
   - 测试专用方法清理：删除服务宿主上仅用于将测试桩塞入底层引擎实现的私有测试桥接，引导测试直接面向引擎或宿主各自的真实接缝测试。

4. **保持双向依赖解耦与单向拓扑（Unidirectional Architecture）**：
   - 依赖流严格单向：`domain.session` -> `domain.player` (接口) <- `data.player` (实现)；`data.service` (宿主) 依赖 `domain.player` 和 `domain.session`，无反向反哺。
   - 接口职责极简化：流式管道接缝保持在最窄集合，仅负责装载音轨、预卷、元数据无感更新与基础回放。

## Testing Decisions

1. **接口即测试表面（The Interface is the Test Surface）**：
   - 宿主测试专注于验证前台服务提升、15 分钟延迟降级定时器、系统通知内容生成以及 Becoming Noisy 暂停分发，不再断言底层硬件锁的锁持有状态；
   - 引擎测试专注于验证物理音频流加载、无感元数据富化、低采样率重采样以及在播放/缓冲/暂停状态下的硬件锁正确申请与释放；
   - 移除测试中所有跨接缝强转与幽灵桩（如模拟双向反向回调的假引擎），生产代码怎么走，测试就怎么测。
2. **测试模块覆盖**：
   - 系统宿主套件：验证前台服务状态机与通知广播；
   - 播放引擎套件：验证真实流式管线与硬件休眠锁治理；
   - 端到端回归套件：验证系统音频焦点、外放拔出保护、路由切换刷新与后台保活零回归。
3. **既有参考（Prior Art）**：
   - 遵循 ADR-0016（流式渲染管道窄接口）与 ADR-0018（系统意图单向收拢至会话）的设计约束。

## Out of Scope

1. 更改 CUE 虚拟分轨在会话层的调度算法（此为候选方案 2/3 的范畴）。
2. 更改 ExoPlayer 内部的网络缓冲大小配置（StreamingLoadControlConfig）。
3. 变更 UI 展现层与组件布局。

## Further Notes

本次重构属于架构加深与接缝净化，不改变任何对外可见的用户功能与播控协议，完全在编译期与架构层消除摩擦，为未来的稳定迭代筑牢根基。
