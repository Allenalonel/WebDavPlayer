# Spec: CUE 虚拟分轨与流式无缝衔接 (CUE Virtual Tracks & Streaming Gapless Playback)

Status: completed

## Problem Statement

发烧友用户在 WebDAV 云端或 NAS 存储中收藏了大量以整轨抓轨文件（如单个 FLAC、WAV、APE 文件，大小达数百兆）配对同目录 `.cue` 文件的无损音乐专辑。当前播放器将整轨音频视为单一不可分割的音频文件，用户无法直接点选具体曲目、无法进行曲目间切歌，且无法在界面和系统通知中查看各分轨的真实曲名与表演者。

此外，在纯流式、无本地持久化磁盘缓存的既有架构约束下，常规独立曲目在切歌与自然顺延时，ExoPlayer 默认会经历断开连接、重新发起 HTTP Range 请求、重新嗅探格式探针并重建音频输出链路的过程，造成 0.5 秒至 2 秒不等的声学停顿（Acoustic Gap）。整轨音乐专辑（如交响乐、现场演唱会、概念唱片）对曲目衔接的连贯性要求极高，任何声学间隙都会严重破坏聆听沉浸感。

同时，用户明确拒绝了“播完自动跳入下一个文件夹”的跨目录无限跳转逻辑，要求播放行为严格约束在当前目录内，并在播完最后一首时自然回环至第一首（Folder Ring 闭环循环）。

## Solution

1. **单物理流 + 逻辑虚拟轨（Single Physical Stream + Logical Virtual Tracks）**：
   引入无依赖的纯状态机 CUE 解析器，直接在内存中将整轨大音频拆解为有序的 `Virtual Track` 集合。底层流媒体引擎始终维持单一持久化的 HTTP 流式连接，不切断网络、不重建解码器；在播放跨越分轨时间戳时，依靠会话层的虚拟时间轴映射引擎（Virtual Timeline Engine）实现零打扰分轨元数据广播（Non-Disruptive Metadata Enrichment），向系统通知栏与 UI 实时呈现分轨信息，达成物理级绝对无缝回放（Bit-Perfect Gapless）。

2. **双轨预卷流式缓冲（Pre-roll Stream Buffering）**：
   针对普通独立多曲目场景，保持 OkHttp 专用长连接池保活，并通过播放器双轨交叠预热机制，在当前曲目接近尾声时提前装填下一曲目的前导音频流与格式探针，实现普通曲目切换时的零网络等待无缝衔接。

3. **文件夹环形循环（Folder Ring Playback）**：
   将播放队列的拓扑范围严格锁定在当前活跃远程目录。列表循环模式下，当播放到达目录末尾曲目时，自动无缝回环至首曲，严禁跨目录越界。

## User Stories

1. 作为音乐发烧友，当我在目录中看到附带 `.cue` 文件的整轨音频专辑时，我希望播放器能自动或点击解析该 `.cue` 文件，以便我能看到整张专辑完整的分轨列表。
2. 作为音乐发烧友，我希望在分轨列表中能清晰看到每首分轨的序号、曲目标题、表演者以及该分轨的精确时长，以便快速了解专辑结构。
3. 作为用户，我希望在分轨列表中点击任意一首虚拟分轨，播放器能瞬间从该分轨的起始时间戳开始流式播放，以便我想听哪首就听哪首。
4. 作为现场音乐与古典乐爱好者，我希望整张 CUE 专辑从第一首连续播放到最后一首时，曲目交界处没有任何可感知的爆音、静音卡顿或重缓冲，以便享受原汁原味的录音连贯性。
5. 作为用户，当我正在播放某首虚拟分轨时，我希望全屏大播放器和迷你播放条显示的进度条与时间文本是针对当前分轨的相对进度（例如 `01:23 / 04:12`），而不是整张专辑全局的几十分钟，以便直观感知当前单曲进度。
6. 作为用户，当我拖拽进度条 Seek 时，我希望 Seek 范围被限制在当前虚拟分轨的起止区间内，以便我不小心拖过头跳出当前曲目。
7. 作为用户，当一首虚拟分轨播放完毕自然进入下一首时，我希望系统通知栏、桌面歌词以及蓝牙车机屏幕上的歌曲标题与艺术家能够立即无缝更新，而底层音乐完全不中断。
8. 作为用户，当我在全屏播放器或通知栏点击“下一首”时，播放器能立即 Seek 跳转到下一首虚拟分轨的开头，若处于内存流式缓冲内则实现 0 毫秒秒切。
9. 作为用户，当我在播放某首虚拟分轨时点击“上一首”，如果播放已超过 3 秒则回到当前分轨开头；如果在 3 秒内则跳回上一首虚拟分轨开头，符合主流播放器的人性化习惯。
10. 作为用户，我希望 CUE 的解析与虚拟分轨完全在内存中完成，不向本地持久化磁盘写入任何缓存文件，严格遵守无本地磁盘缓存的设计原则。
11. 作为用户，在播放由独立文件组成的普通文件夹时，我也希望上一首播完到下一首开始之间没有任何可感知的空白断音，体验如实体 CD 般顺滑。
12. 作为用户，我希望当播放模式为“列表循环”且播放到文件夹最后一首歌时，播放器能够自动无缝循环回到当前文件夹的第一首歌继续播放，而不是停止或擅自跳转到其他文件夹。
13. 作为用户，当我在远程目录中离开应用后再重新启动时，播放现场恢复（Playback Session State）能够精确还原我正在收听的具体虚拟分轨以及分轨内的相对播放进度。
14. 作为用户，如果某个 `.cue` 文件存在语法错误或其指向的目标音频文件不存在，我希望应用能给出温和的错误提示并允许我直接以普通大文件播放，而不发生应用崩溃。
15. 作为用户，在目录列表中浏览时，我希望当前正在播放的虚拟分轨所在的大文件能显示动态跳动的等化器指示器（Equalizer Track Indicator），让我清楚知道正在播放的内容。
16. 作为用户，在播放队列抽屉（Playback Queue Bottom Sheet）中，我希望能看到展开后的所有虚拟分轨项，并能随意点击跳转。

## Implementation Decisions

### 1. 领域模型与契约定义 (Domain Contracts)
- **Virtual Track 领域实体**：定义包含 `trackNumber`、`title`、`performer`、`startTimeMs`、`endTimeMs`、`parentAudioPath` 的纯领域数据结构，严禁混入 Android 框架依赖。
- **Playback Queue 容器深化**：扩展现有的 `PlaybackQueue` 领域对象，支持装载常规 `AudioTrack` 与内联展开的 `Virtual Track`，对外提供统一的队列索引与上下曲导航抽象。
- **Folder Ring Playback 循环策略**：收敛播放流转边界，当队列索引溢出且处于列表循环状态时，索引重置为 `0`，禁止调用目录扫描器寻找兄弟目录。

### 2. 纯内存 CUE 状态机解析器 (In-Memory CueParser Module)
- **轻量独立模块**：实现无第三方库依赖的流式文本解析器，通过行状态机提取 `FILE`、`TRACK`、`TITLE`、`PERFORMER`、`INDEX 01` 等关键标签。
- **时间帧精准换算**：将 CUE 标准的 `分:秒:帧`（每秒 75 帧）精确换算为毫秒级数值（`1 frame = 1000 / 75 ms`）。
- **生命周期策略**：采用点选按需解析与纯内存瞬态驻留，不持久化入 Room 数据库，完全契合纯流式与零磁盘沉淀的设计红线。

### 3. 会话层虚拟时间轴映射引擎 (Virtual Timeline Engine)
- **双向时间映射**：在播放会话实现层中，维护底层播放器全局物理进度（`globalPositionMs`）与当前激活虚拟分轨相对进度（`virtualPositionMs`）的实时换算：
  - `virtualPositionMs = (globalPositionMs - activeTrack.startTimeMs).coerceAtLeast(0L)`
  - `virtualDurationMs = activeTrack.durationMs`
- **自然边界跨越检测（Boundary Detection）**：会话层高频 Ticker 监听到 `globalPositionMs >= activeTrack.endTimeMs` 时，自动递增当前虚拟分轨索引，并触发 `Non-Disruptive Metadata Enrichment`，将新分轨的元数据推送给系统 MediaSession，绝不调用底层播放器的重新加载接口。
- **Seek 与步进控制接管**：对上层暴露的 `seekTo(ms)`、`next()`、`previous()` 统一在会话层换算为物理流的绝对目标毫秒，再委派给底层播放引擎执行流内定位。

### 4. 传输层双轨预卷与连接池复用 (Streaming Pre-roll & Connection Pool)
- **持久连接池配置**：OkHttp 客户端保持持久化 Keep-Alive 连接池（空闲超时 5 分钟，至少保留 4 个空闲长连接），确保切歌请求复用同一 TCP/TLS 通道。
- **ExoPlayer LoadControl 调优**：调整流媒体缓冲策略，保留 10 秒回退缓冲区（Back Buffer），并在当前音轨播放进入末尾安全窗口时，触发底层对下一项的 Header 预读与解码器无缝交叠馈送。

### 5. 会话现场持久化扩展 (Playback Session State Schema)
- 扩展现有的 DataStore / Room 会话状态模型，在保存当前播放上下文时增加可选的 `cuePath` 与 `virtualTrackIndex` 字段。在应用冷启动恢复时，若检测到该字段，先行建立物理长音频连接，再静默 Seek 至分轨目标进度，实现零感知续播。

## Testing Decisions

### 1. 良好测试准则
- 仅测试模块的公开交互行为与状态流转，绝不刺探解析器内部正则或会话层私有变量。
- 绝不在测试中引入网络真实请求或磁盘 IO，全部使用虚拟时间（Standard Test Dispatcher）与纯内存虚拟源。

### 2. 测试覆盖矩阵
- **CUE 状态机解析测试**：
  - 测试各种常见 CUE 变种格式（含双引号/无引号、多空白字符、含 REM 注释、跨音轨单双盘标记等）。
  - 测试时间戳分秒帧换算的毫秒精度边界条件。
  - 测试非法格式、缺失 FILE 标签或时间戳倒流时的降级与容错。
- **虚拟时间轴换算与边界跳跃测试**：
  - 验证全局进度向局部进度的换算公式。
  - 验证当全局时间跨越分轨分界点时，元数据广播事件被正确且仅触发一次。
  - 验证切到上一曲/下一曲时的毫秒换算与安全边界截断（Clamp）。
- **Folder Ring 闭环队列测试**：
  - 验证到达目录末尾且处于循环模式时，下一首正确返回第 0 首，绝不抛出越界异常。
- **会话现场保存与恢复测试**：
  - 验证包含虚拟分轨信息的会话数据能被完整序列化并在反序列化后精准还原播放进度。

### 3. 代码库先例 (Prior Art)
- 参考 `LrcParserTest` 中的纯状态机解析测试范式。
- 参考 `MusicPlayerAppSessionImplTest` 中的会话状态监听与动作驱动测试。

## Out of Scope

- 写入或反向修改 WebDAV 服务器上的 `.cue` 文件（播放器保持只读）。
- 跨父级或跨同级兄弟文件夹的自动无限连播（经与用户讨论，明确排除此特性）。
- 将 WebDAV 音频文件下载或持久化缓存到手机本地磁盘。
- 解析内嵌在音频元数据标签（ID3v2 GEOB/TXXX）中的内联 CUE（首期仅聚焦同目录外置 `.cue` 文件）。

## Further Notes

- **弱网容错**：由于整轨大音频体积较大，当用户在较远的分轨间跳跃（如从 Track 1 突然跳到 Track 10）时，若超出已缓冲的内存范围，ExoPlayer 会发出新的 HTTP Range 分片请求。界面应展示平滑的微缓冲状态指示，避免界面假死。
- **蓝牙与车机联动**：通过 `Non-Disruptive Metadata Enrichment` 更新分轨信息时，需确保系统 MediaSession 的 `PlaybackStateCompat` 始终保持 `STATE_PLAYING`，防止某些蓝牙耳机或车机因媒体项变更而误触发暂停。
