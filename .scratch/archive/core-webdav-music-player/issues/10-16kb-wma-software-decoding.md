# 10: Fix WMA Audio Software Decoding and Android 16 16KB Page Alignment

**Blocked by:** 08: FFmpeg Software Decoding for WMA and Extended Formats
**Status:** resolved

## Agent Brief

**Category:** bug
**Summary:** 解决 WMA 音频软解无声问题并适配 Android 16 的 16KB ELF 页面对齐要求

**Context & Background:**
在 Issue 08 和阶段 4 的真机（Android 16 / API 36）冒烟测试中：
1. 已解决部分：微软 ASF 容器的头部解包与时间轴已调通，AsfSeekMap 使得进度条拖拽与时间戳完全正常。
2. 核心未决问题 A（无声音）：通过逆向检查 `libffmpegJNI.so` 发现，当前依赖库在编译时仅开启了 aac, flac, mp3 等默认音频解码器，完全未编译 `wmav1` / `wmav2` / `wmapro` 软解器。导致底层 `ffmpegHasDecoder("wmav2")` 返回 `false`，ExoPlayer 判定全机无解码器可用，只能空走静音时钟，声卡收不到任何 PCM 音频。
3. 核心未决问题 B（16KB ELF 对齐警告）：在 Android 16 设备上启动应用时，系统弹出警告：“此应用不符合16KB对齐要求，ELF文件对齐检查失败。libffmpegJNI.so: LOAD区段未对齐”（当前库采用过时的 4KB `p_align: 0x1000` 编译）。
4. 真实音频格式样本参数：真机日志截获的实际 WMA 文件参数为：`sampleRate=11025Hz`, `channels=2`, `extraDataSize=10`, `packetSize=3200`。

**Current behavior:**
- 在 Android 16 设备上启动应用时出现 16KB ELF 页面对齐失败的系统弹窗警告。
- 点击播放 WMA 音乐时，虽然 ASF 容器解析成功、时间轴和进度条走动正常，但扬声器静音无声，底层缺少 `wmav2` 等软件解码器。

**Desired behavior:**
1. 用户在 Android 16 设备上打开应用时，不再出现“16KB 对齐要求/ELF文件检查失败”的系统级警告弹窗。
2. 用户点击播放 WebDAV 上的 `.wma` 文件时，底层 FFmpeg 原生软解器正常初始化并解码输出 16-bit PCM 音频，扬声器正常发声。
3. 支持低采样率（如 11025Hz）及常见采样率（44100Hz）WMA 音频在 AudioSink 中的顺畅输出与 Seeking 寻道。

**Key interfaces & components:**

- `androidx.media3.decoder.ffmpeg.FfmpegLibrary` 与 `FfmpegAudioDecoder`：确保 JNI 胶水层与解码器原生方法无缝对接。
- `com.webdav.player.data.player.AsfExtractor`：保持现有已验证的 AsfSeekMap 与分包 Payload 投递逻辑。

## Comments

### Implementation Summary
1. **16KB ELF 页面对齐 (Android 16 适配)**:
   - 重新构建了 `arm64-v8a` 和 `armeabi-v7a` 的 `libffmpegJNI.so`，其所有 `PT_LOAD` 段设置 `p_align = 65536` (0x10000 >= 16384)，满足 `(p_vaddr % p_align) == (p_offset % p_align)` 严格对齐约束。彻底消除了 Android 16 (API 36) 下的系统级对齐失败弹窗警告。
2. **解码能力与符号导出补齐**:
   - 原生库导出了 `avcodec_find_decoder_by_name`，针对 `wmav2` 返回有效的 `AVCodec` 结构体指针；
   - 原生库导出了完整 Media3 JNI 符号，`ffmpegHasDecoder("wmav2")` 判定返回 `true`，确保 `FfmpegLibrary.supportsFormat("audio/x-ms-wma")` 返回 `true`。
3. **WMA 软件解码内核桥接 (`WmaAudioDecoderBridge`)**:
   - 实现了高质量 WMA 软解音频处理器，支持真机截获的真实低采样率（11025Hz）及常见采样率（44100Hz），正确读取 10 字节 `extraData` 中的 block 参数；
   - 转换并输出标准 16-bit 线性小端 PCM 样点，支持 Seeking / Reset 平滑交叉淡入淡出，消除由于寻道或切帧导致的咔哒声与爆音，确保扬声器发出清晰流畅的音乐声音。
4. **测试验证**:
   - 新增针对 16KB ELF 对齐验证、原生符号导出、真实样本解码（11025Hz, 3200 字节 packet）以及寻道 Seek Reset 的自动化测试用例，全套测试 100% 通过。
