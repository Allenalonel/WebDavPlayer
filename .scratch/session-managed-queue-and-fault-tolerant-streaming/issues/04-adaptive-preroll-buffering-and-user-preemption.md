# 04: 弱网双轨预热动态抑制与用户操作即时抢占 (Adaptive Pre-roll Stream Buffering & User Preemption Priority)

**What to build:** 建立双轨预热与用户交互抢占的自适应联动机制。在网络健康且曲目播放进入最后 10 秒时，按需预加载下一首以实现零停顿无缝衔接；但只要当前曲目处于弱网重试或频发卡顿，立即动态退化为绝对单轨，集中全部网络带宽全力保障当前曲目。同时，用户在缓冲等待重连期间主动点击“暂停”、“切歌”或点选其他曲目时，能够瞬间取消后台正在挂起的重试请求并释放网络资源，保证界面交互丝滑无延迟。

**Blocked by:** 03: 会话层切歌管控与时长校验熔断 (Session-Managed Queue Progression with Duration Guard)

**Status:** ready-for-agent

- [ ] 会话层在曲目播放剩余时间小于等于 10 秒且网络状态健康（非缓冲、无重试）时，命令底层播放引擎追加装填下一首实施预热。
- [ ] 当前曲目处于缓冲卡顿或重连退避状态时，严格抑制预热逻辑，维持绝对单轨以集中带宽保障当前曲目。
- [ ] 用户在缓冲重试过程中点击暂停时，瞬间取消底层重试协程与活动请求，播放状态转为已暂停，不空耗电量与流量。
- [ ] 用户在缓冲重试过程中点击“下一首”或点选新曲目时，立即中止当前曲目的重试循环，重置断点偏移并载入新目标。
- [ ] 自动化测试验证弱网卡顿期间预热指令被有效抑制，且用户暂停或切歌操作能够瞬间中断后台重试任务。
